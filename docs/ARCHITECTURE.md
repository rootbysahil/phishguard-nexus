# PHISHGUARD//NEXUS — Architecture

> Phase 0 planning document.
> System architecture, repository structure, component responsibilities, and execution flow.

---

## 1. System Overview

PHISHGUARD//NEXUS is an end-to-end, explainable AI phishing and scam detection platform. A user submits a URL, email text, or SMS message; the system processes it through a multi-stage ML pipeline and returns a calibrated verdict, per-feature SHAP contributions, and an advisory explanation generated by IBM watsonx.ai Granite (with an offline rule-based fallback).

All operations are observable: the backend streams pipeline milestones to the frontend in real time via Server-Sent Events (SSE), feature weights are visualised transparently, and all model evaluation metrics are reproducible via `make train`.

## 3. Component Responsibilities & Concurrency Model

### 3.1 Backend — FastAPI (Async + Thread Pool)

FastAPI handles network I/O asynchronously, but machine learning inference and SHAP calculations are CPU-bound. To prevent CPU tasks from blocking the async event loop (which would freeze SSE streaming and delay active connections):
- **Thread Pool Offloading**: All calls to `url_features.extract()`, `predictor.predict()`, and `explainer.explain()` are wrapped in `asyncio.to_thread()` executing within a dedicated `concurrent.futures.ThreadPoolExecutor`.
- **SSE Channel Management**: Each scan registers an in-memory `asyncio.Queue` tagged with `scan_id`. Events are pushed to the queue as stages complete.
- **Heartbeats & Memory Leak Prevention**:
  - SSE streams emit an empty comment keepalive (`: ping\n\n`) every 5 seconds.
  - Queues are strictly evicted from memory upon emitting the terminal `done` event or after a 60-second idle disconnect timeout.

### 3.2 Frontend — React + Vite

| Component | Responsibility |
|---|---|
| `ScanConsole` | Handles URL, plain email, and SMS input. Supports `.eml` drag-and-drop. |
| `.eml` Browser Parser | Uses client-side MIME parsing (e.g. `mailparser-mit` / `eml-format`) with a **strict 5 MB limit**. Parses plain text and links in the browser; the raw file is never uploaded. |
| `PipelineAnimation` | Subscribes to `/api/scan/stream/{id}` via EventSource; renders real progress percentages. |
| `ThreatGauge` | Visualises risk probability. Threshold colors are configured dynamically from `GET /api/config`. |
| `UrlAnatomy` | Deconstructs URL segments; highlights homoglyphs and typosquats against known brands. |
| `ExplainabilityPanel` | Renders SHAP contribution bars (magenta for risk, cyan for safe). |
| `AiAnalyst` | Streams English explanation first. Triggers on-demand translation to Hindi / Punjabi via `POST /api/translate`. |
| `ThreatMap` | Interactive Three.js globe. Uses fixed anchor coordinates; **never queries user IP geolocation**. |

## 4. End-to-End Scan Execution Flow

```text
User Input (URL / Email Text / SMS)
  │
  ▼
POST /api/scan
  │  ← Input validation: URLs <= 2,048 chars, text <= 50 KB (HTTP 413 if exceeded)
  │  ← Creates scan_id, initializes bounded asyncio.Queue
  │  ← Returns HTTP 202 Accepted {scan_id: "...", stream_url: "/api/scan/stream/..."}
  │
  ├── Client opens GET /api/scan/stream/{scan_id} (SSE)
  │   └── Emits ': ping' keepalive every 5s
  │
  ▼
Stage 1: PARSE (async)
  │  URL: parses scheme, domain, eTLD+1 via tldextract, path, and query tokens
  │  Email/SMS: extracts embedded hyperlinks and strips HTML formatting
  │  → SSE: {stage: "parse", pct: 15, detail: "Deconstructing input tokens"}
  │
  ▼
Stage 2: FEATURE EXTRACTION (via asyncio.to_thread)
  │  Runs pure-Python lexical feature extractors in background thread pool
  │  → SSE: {stage: "features", pct: 40, detail: "Extracted 28 lexical features"}
  │
  ▼
Stage 3: OPTIONAL HOST LOOKUP (guarded, timeout = 2.0s)
  │  If HOST_FEATURES_ENABLED=true: queries RDAP domain age and DNS A-records
  │  Private/loopback IP address ranges blocked (SSRF guard)
  │  → SSE: {stage: "reputation", pct: 60, detail: "Domain reputation checked"}
  │
  ▼
Stage 4: ML INFERENCE (via asyncio.to_thread)
  │  Runs LightGBM pipeline in worker thread
  │  Computes raw log-odds score → applies isotonic calibration → assigns verdict
  │  → SSE: {stage: "inference", pct: 80, detail: "Probability calibrated"}
  │
  ▼
Stage 5: EXPLAINABILITY & AI ANALYST (asyncio.to_thread + LLM)
  │  explainer.py: computes SHAP feature contributions (top 10)
  │  watsonx_provider.py: generates plain-English explanation (offline template if unreachable)
  │  → SSE: {stage: "explain", pct: 95, detail: "AI analyst explanation generated"}
  │
  ▼
Stage 6: PERSISTENCE & COMPLETION
  │  Writes record to SQLite:
  │  - URL/domain stored in plaintext for dashboard history & search
  │  - Raw email/SMS body is NEVER stored (SHA-256 hash retained for deduplication only)
  │  → SSE: {stage: "done", pct: 100, scan_id: "..."}
  │  Queue evicted from server memory; SSE stream closed cleanly
```

## 5. Security & Privacy Architecture

1. **Strict Zero-Fetch Lexical Default**: The server never issues HTTP GET requests to scanned URLs. Analysis is performed strictly on lexical string properties and domain metadata.
2. **SSRF Guard**: If optional host lookups are enabled, target domains are validated to ensure they do not resolve to RFC 1918 private IP addresses or loopback ranges.
3. **Prompt Injection Defense**: The LLM prompt is populated only with structured, machine-extracted features (verdict, confidence, top SHAP attributes). Raw user input is never concatenated directly into prompts.
4. **Data Privacy**:
   - **URLs/Domains**: Stored in SQLite to power the local scan history and search dashboard.
   - **Email / SMS Texts**: Content bodies are discarded from memory immediately after inference; only a SHA-256 hash is logged.
   - **Client IP**: User IP addresses are never transmitted to external geolocation services.
5. **Payload Bounds**: URL inputs are restricted to 2,048 characters; email/SMS bodies are capped at 50 KB. Oversized inputs receive an immediate HTTP 413 response.

## 6. Deployment Architecture

`docker compose up` provisions the full environment:

| Service | Container Port | Host Port | Technology | Notes |
|---|---|---|---|---|
| `backend` | 8000 | 8000 | FastAPI / Uvicorn | Mounts SQLite file & `models/` directory |
| `frontend` | 80 | 3000 | Nginx (prod) / Vite | Proxies `/api` routes to backend container |

CI runs through `.github/workflows/ci.yml` verifying linting (`ruff`, `eslint`), unit test coverage (`pytest`, `vitest`), and container builds.
